# M3 deterministic synthetic test matrix

**Reconciled design.** These scenarios are future acceptance criteria. All authorities, schedules, records, permits and IDs are synthetic. The Owner column identifies the first PR that must demonstrate each case. Later PRs retain earlier regression coverage. [Rule evaluation contract](M3_RULE_EVALUATION_CONTRACT.md)

## Shared fixtures

- `B` is a synthetic fixture for the exact target `R1/G1/O1/LEFT`, with a base permission and explicit coverage for the listed intervals. Synthetic restriction assumptions bind the relevant rule and interval. The base permission is conditional on its named restrictions. PR-03 conflict cases model explicit precedence separately. Fixtures simulate facts and approvals without asserting real coverage or authority.
- Default inputs model a passenger vehicle and verified absence of applicable permits. January 2026 local shorthand denotes instants at offset `-05:00`. PR-01 fixtures construct absolute UTC `time.Time` values directly. PR-02 uses the same target with `America/New_York` and pinned fixture timezone data for civil-time cases. Later integration fixtures add dataset, artifact, batch, release and version identities under a fixed synthetic assessment clock.
- **P** in the provenance column means bind the requested stay, target and exact fixture rule/evidence references. PR-01 needs only fixture provenance. PR-02 adds calendar/timezone identity where applicable. PR-03–06 add their modeled reviews, release lineage, authorizations and replay pins. **Audit P** preserves those pins under a separately authorized historical purpose. **No P** means no legal proof or partial intervals may be returned.
- **P**, **X** and **U** in the Result column mean `COMPLETE / PERMITTED`, `COMPLETE / PROHIBITED` and `COMPLETE / UNKNOWN`. **I** is `INVALID_INPUT / UNKNOWN`. **F** is `FAILED / UNKNOWN`. Every completed case asserts a positive-length, exact UTC partition that covers the stay without gaps or overlap, with interval outcomes, reasons and references. Invalid or failed cases assert empty intervals. Stable reason codes apply at the relevant interval or whole-stay level.

### T47 budget cases

Use synthetic fixtures and keep the other independent work counts within their limits. Each limit-plus-one case must yield `FAILED / UNKNOWN / EVALUATION_LIMIT` with empty intervals and no legal proof.

| Work count | At the inclusive limit | At the limit plus one |
|---|---|---|
| Rules | 256 full-stay rules with distinct IDs and compatible effects, one absolute interval each. Supply complete fixture coverage and expect normal evaluation. | Add the 257th rule. |
| Raw temporal windows | One full-stay permission and 1,023 identical full-stay coverage windows. Total 1,024 raw entries and 2,050 endpoint entries charged before deduplication, with only two unique boundaries. Expect P with the same proof and single interval as the fixture with one copy of coverage. | Add one identical coverage window for 1,025 raw entries. The number of unique boundaries is still two. Reject in raw preflight before allocating sweep storage. |
| Raw temporal windows across input kinds | Use a full-stay decisive restriction starting at the first boundary and its scoped assumption. Build the rest of the 1,024 entries from coverage, assumptions, permit facts and unresolved records, including duplicate, disjoint and implicit whole-stay windows. The scoped assumption establishes that these facts cannot displace the restriction. Expect X with interval proof. | Append one disjoint unresolved window for 1,025 total. Assert the shared count includes entries that would clip out. The early restriction yields no partial result. Repeat with one extra implicit whole-stay fact. |
| Unique temporal boundaries | Within a 1,023-second stay, use 512 one-second coverage windows starting at 0, 2, …, 1,022 seconds. Both request endpoints already coincide with window endpoints. Expect U with 1,024 unique boundaries and a complete partition. | Add the coverage window `[1s, 1.5s)` relative to the stay start. It creates exactly one new boundary, for 1,025, with only 513 raw windows. |
| Evidence references | Use a valid fixture with 2,048 reference entries, including repeated references to the same evidence. Expect the same proof as the deduplicated fixture. | Add one repeated entry for 2,049. Reject during preflight rather than deduplicating to fit. |
