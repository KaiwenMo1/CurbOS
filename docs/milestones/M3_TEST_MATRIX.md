# M3 deterministic synthetic test matrix

**Proposed.** These are acceptance scenarios for future implementation. Every authority, ordinance, schedule, calendar entry, permit, representation and identifier below is synthetic. None describes a real curb or real legal rule. [Rule evaluation contract](M3_RULE_EVALUATION_CONTRACT.md)

## Shared fixtures

- `B` is the base synthetic snapshot for one reviewed west curb target `R1`, represented as `LEFT` against orientation revision `O1`, geometry `G1`, scope `S1`, dataset `D1`, batch `B1` and release `A`. It has rule set `V1`, independently reviewed synthetic approval `A1`, and the `America/New_York` timezone with pinned test tzdata. It grants reviewed base permission for a passenger vehicle and complete, fresh coverage across the listed fixture windows. The baseline permission is explicitly conditional on reviewed restrictions. All named overlays use a fixture-reviewed precedence edge for that condition except in the explicit conflict cases.
- Default request facts are verified passenger vehicle, verified absence of applicable permits, and an exact binding to `R1/G1/O1/LEFT`. The regular winter examples fall in January 2026 and use `-05:00`. Explicit offsets are supplied in executable fixtures. The localized shorthand below always represents half-open intervals. The synthetic assessment clock is fixed and precedes the requested windows. The versioned fixture approval and prescribed coverage support evaluation of those windows as of that clock. Stale and revoked cases explicitly change those facts.
- **P** means the receipt binds the requested stay, assessment instant, scope, dataset/batch/artifact lineage, exact release, target/side/geometry, rule set, approvals, semantics and timezone/calendar hashes. The evidence column lists the required decisive proof or missing relation in addition to P. **Audit P** means the same pins under separately authorized historical purpose. **No P** means no snapshot or proof may be presented for invalid input. A failed or denied live recheck can retain protected audit metadata, with no restricted references in its returned reason.
- `P`, `X`, and `U` in the **Result** column mean `COMPLETE / PERMITTED`, `COMPLETE / PROHIBITED` and `COMPLETE / UNKNOWN`, respectively. `I` means `INVALID_INPUT / UNKNOWN`. `F` means `FAILED / UNKNOWN`. Status and outcome are asserted separately. Check exact outcome, stable expected reason codes and the relevant affected interval/provenance. Additional noncontradictory scoping reasons can be asserted separately.

| T44 | Repeat T01 with reversed rule/evidence ordering, duplicated exact evidence, and replay the sealed inputs twice | P · `FULL_STAY_AUTHORIZED` with identical reference ordering and digest | P + repeatable canonical proof. Acceptance requires table-driven unit tests, explicit boundary/property checks and isolated integration tests as assigned in the [PR plan](M3_PR_PLAN_AND_GATES.md). Unit success validates the proposed mechanics on synthetic facts. Real evidence, production authority and public release have separate gates.
