## ADR compliance and trust boundaries

- **ADR-016** — PostgreSQL/PostGIS owns provenance, releases and pointers. Goose versions the schema. The existing Go pgx path reads the release projection. Disposable databases and explicit test capability roles isolate synthetic publication from ordinary API visibility. This review establishes isolation in the implemented slice. Deployment of separate production and simulation credentials and infrastructure remains a later operational decision.
- **ADR-022** — Source Zone identity, geometry revisions, release keys and physical resource identity remain distinct. The optional resource association can stay null. The discovery projection preserves source lines and makes no capacity, physical identity or occupancy inference.
- **ADR-027** — Three read-only REST routes have a versioned OpenAPI contract, explicit evidence/coverage and error codes, and pinned references. WebSocket reconciliation and private parking sessions belong to later milestones.
- **ADR-028** — The raw store retains hashed bytes and registered lineage. Staging and validation are private, with distinct Policy reference and parse statuses. Exact release versions, compare-and-swap and append-only events protect readers and preserve the prior release after failures. Source geometry changes carry separate evidence identity. Reusing or rejecting old occupancy observations remains an integration obligation when occupancy exists. [Decision register](../architecture/DECISION_REGISTER.md) · [ADR-028](../adr/ADR-028_VALIDATED_STAGING_ATOMIC_PUBLICATION.md)

Local evidence relies on the trusted store owner, original capture authority, PostgreSQL and its administrators. Hashes establish byte identity within that boundary. PostgreSQL enforces distinct publication capabilities, authenticated session identity, digest equality and atomic transitions. The trusted verifier process checks the actual files. A holder of its credentials can attest directly through SQL. Production isolation, credential custody and reviewer authorization therefore remain required evidence. PR-07 checklist references establish subject binding and preserve claims. Independent approval verification remains `NOT_ASSESSED`. Ordinary public reads cannot obtain private payloads or synthetic fixture details. [Publication trust model](../../data/cds_publish/README.md#verify-independently) · [Assessment reader grants](../../data/cds_readiness/reader_privileges.sql) · [Discovery privileges](../../db/migrations/00005_m2_discovery_reads.sql)

## Migrations, rollback and retention

The repository has Goose `00001` (PostGIS), `00002` (evidence), `00003` (publication), `00004` (independent verifier), `00005` (Discovery reads), and `00006` (scope withdrawal read fix). Clean application to version 6 and repeatability are verified in disposable PostgreSQL/PostGIS. Production migration application is **NOT_ASSESSED**. PR-07 adds a separately provisioned private reader grant script and has no migration. [Migration directory](../../db/migrations) · [Database smoke gate](../../tests/db/smoke.sh)

Operational rollback selects a previously active, still-eligible frozen version with CAS and a new event. Withdrawal clears the scope pointer and closes historical serving while retaining the releases and events. Schema Down is destructive and reserved for disposable testing. The publication Down guards protect existing registrations, fixture enrollment and audit history. The `00004` upgrade stops for legacy registration or activation history and requires independent review. Reverting `00006` restores the earlier read behavior, so retain it while Discovery is served. Preserve the database and private evidence stores together, including content hashes, approval receipts, and activation events.
